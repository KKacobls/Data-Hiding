封包格式（V4）

[ 16-bit Magic (0xDE01) ] ← 已隱寫 + 演算法 DE
[ 8-bit INDEX_BITS ] ← 見下方公式（INDEX_BITS1 = INDEX_BITS2，全封包共用，只寫一次）
[ 32-bit n ] ← 溢位點數量
[ INDEX_BITS1 × n ] ← Iovf索引清單
[ 8-bit 檔名長度 ] ← 檔名 UTF-8 位元組數
[ 檔名 × 8 ] ← 檔案名稱
[ 16-bit Iweak 數量 ] ← strict walk 前綴跳過的弱配對數
[ INDEX_BITS2 × Iweak ] ← Iweak索引清單
[ 32-bit M ] ← DATA 長度（bits）
[ DATA (M bits) ] ← 承載區（strict 槽）
[ 32-bit CRC 校驗碼 ]
INDEX_BITS1 / INDEX_BITS2 怎麼算？
N = 圖像素對總數（灰階 = 像素÷2；彩色 BGR 拉平 = 像素×3÷2）
INDEX_BITS1 = INDEX_BITS2 = max(1, bit_length(N)) ← 要能表示 1…N 的 1-based 圖組號
Iovf = INDEX_BITS1 × n ← 溢位索引清單總 bits
Iweak區 = INDEX_BITS2 × 弱配對數量 ← 弱配對跳過清單總 bits
H = 16 + 8 + 32 + Iovf + 8 + 檔名×8 + 16 + Iweak區 + 32 ← 標頭保留 bit 數（至 M 之前）
INDEX_BITS1 與 INDEX_BITS2 數值相同，但對應不同索引清單（Iovf 筆數 = n，Iweak 筆數 = 弱配對數量）。

灰階直接 DE；彩色圖 BGR 拉平（×3 容量）。CRC32 使用 zlib.crc32()，僅對 DATA 計算。
Iweak 清單：嵌入 strict 槽時 walk 跳過的弱配對寫入標頭；解碼讀取後跳過，避免 ghost maybe。

演算法流程

嵌入：標頭寫入第 0 組起連續安全區（含 Iweak 索引清單）→ 承載區 strict 槽寫 DATA+CRC（跳溢位 + 跳弱配對）
提取：標頭連續讀 → 讀 Iovf / Iweak 索引清單 → 承載 walk 依 Iweak 排除 ghost → 驗 CRC32
彩色：B→G→R 拉平，同一套流程
